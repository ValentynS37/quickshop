# BADS AI Administrator — Decision Log

## 2026-07-15

### Decision: validate through a managed pilot before building a full SaaS platform

**Reason:** client workflow, KPI, integration cost and evidence requirements must be validated with real demand.

### Decision: use a static interactive demo for outreach

**Reason:** it demonstrates the commercial flow without exposing client data or requiring production integrations.

### Decision: keep external actions human-approved

**Reason:** messages, payments, contracts, deletion, permission changes and production deployments create material risk.

### Decision: start with three warm pilot targets

- Amazinum;
- BIG Language Solutions / 911 Interpreters workflow;
- UFuture / innovation ecosystem workflow.

### Decision: separate SMB AI Administrator pricing from enterprise TrustOS pricing

**Reason:** the AI Administrator pilot is a limited managed automation service. Enterprise TrustOS, on-prem and high-risk deployments require separate feasibility, security and commercial review.

### Decision: build BADS-specific evidence and approval logic, not a new orchestration engine

**Reason:** existing orchestration and model infrastructure can support validation while BADS focuses on provenance, evidence, guardrails and operator control.
